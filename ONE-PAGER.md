# ONE-PAGER: План-наряд в рапорте

## Проблема

ИТР подрядчика на стройплощадке слабый. Бригады «разбегаются» и делают работы не там и не то, что нужно по технологии. Наших ИТР (РС) недостаточно, чтобы управлять каждой бригадой вручную 24/7. Результат — потери в сроках, переделки, нарушение технологической последовательности.

## Решение

**Превратить рапорт из «зеркала заднего вида» в навигатор.**

Система ежедневно генерирует план-наряд для каждого подрядчика — что делать, где (секция, этаж) и в каком объёме. Основа — эталонная технологическая последовательность. РС подтверждает или корректирует. Подрядчик получает чёткое задание и отчитывается до 20:00. Система сверяет план с фактом.

## Как это работает

```
┌──────────┐     ┌──────────┐     ┌──────────┐     ┌──────────┐
│  06:00   │     │ 08-10:00 │     │  до 20:00│     │  20:00   │
│ Система  │────▶│   РС     │────▶│Подрядчик │────▶│ Система  │
│генерирует│     │проверяет/│     │выполняет │     │ сверяет  │
│план-наряд│     │корректир.│     │отчитыв.  │     │план/факт │
└──────────┘     └──────────┘     └──────────┘     └──────────┘
      ▲                                                  │
      │              Эталонная                           │
      └──────── техпоследовательность ◀──────────────────┘
                   (обратная связь)
```

## Четыре контрольных сценария

| | Отметил в системе | Не отметил |
|---|---|---|
| **Сделал по плану** | ✅ Молодец | 🟡 СК ловит через чек-лист |
| **Сделал не по плану** | ⚠️ Разбор с РС | 🔴 СК ловит → эскалация |

## Аналитика

**По РСам:**
- Кто не выдаёт план-наряд → алерт ДС/ДП
- Кто выдаёт не по техпоследовательности → обучение/разбор

**По подрядчикам:**
- % выполнения план-наряда
- % отклонений по месту и виду работ
- Дисциплина подачи факта

## Гранулярность

- **Что:** вид работ (из эталона техпоследовательности)
- **Где:** секция × этаж
- **Кому:** на каждого подрядчика (по кол-ву подрядчиков на объекте)
- **Когда:** ежедневно

## Ключевые принципы

1. **Система предлагает — РС решает.** Автогенерация по эталону, но РС всегда может скорректировать с обоснованием.
2. **Прозрачность в обе стороны.** Подрядчик видит задание, РС видит исполнение, ДС видит управление.
3. **Отклонение — не ошибка, а данные.** Каждое отклонение от плана фиксируется и анализируется. Не наказание, а обратная связь.
4. **СК — независимая верификация.** Чек-листы СК — страховочная сетка для случаев, когда подрядчик не отмечает или врёт.

## Целевые метрики (6 месяцев после запуска)

| Метрика | Цель |
|---------|------|
| Подрядчики с ежедневным заданием | >90% |
| Подача факта до 20:00 | >85% |
| Выполнение работ по плану | >75% |
| РСы, выдающие план-наряд ежедневно | >90% |
| Время реакции на отклонение | <4 часов |

## Точки входа для подрядчика

1. **Telegram-бот** — получает план-наряд утром, отмечает факт вечером (упрощённый интерфейс)
2. **Рапорт (веб/мобильный)** — полная версия с деталями

## Что нужно для запуска (MVP)

| Компонент | Описание | Оценка |
|-----------|----------|--------|
| Эталон техпоследовательности | Загрузка и хранение в системе | Есть в системе |
| Генератор план-наряда | Автоматическое формирование из эталона + текущий прогресс | Разработка |
| Экран РС в рапорте | Просмотр, корректировка, подтверждение | Разработка |
| Экран подрядчика | Получение задания, ввод факта | Разработка |
| Движок сверки | Сравнение план/факт, классификация отклонений | Разработка |
| Интеграция с ботом | Нотификации + упрощённый ввод факта | Доработка бота |
| Дашборд ДС/ДП | Аналитика по РСам и подрядчикам | Разработка |

## Риски

| Риск | Вероятность | Митигация |
|------|-------------|-----------|
| РСы саботируют (не подтверждают план-наряд) | Средняя | Алерт ДС в 10:00 + метрика в аналитике |
| Подрядчики не пользуются ботом | Высокая | Бот максимально простой (2 кнопки), обучение |
| Эталон не соответствует реальности | Средняя | Обратная связь от РСов, версионирование |
| Слишком много корректировок РСом | Средняя | Аналитика отклонений, разбор с ДС |

## Эффект

**Для компании:** прозрачность управления на площадке, данные для принятия решений по подрядчикам и РСам, снижение потерь от нарушения техпоследовательности.

**Для РС:** не нужно придумывать задания — система предлагает. Фокус на управлении отклонениями, а не рутине.

**Для подрядчика:** чёткое понимание что от него ждут. Нет «я не знал» — задание зафиксировано.

**Для ДС/ДП:** впервые видят аналитику по качеству управления РСов и дисциплине подрядчиков.
